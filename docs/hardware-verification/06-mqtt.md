# 06 · MQTT

The broker connection, its reconnect ladder, and commands that arrive over MQTT. Discovery,
availability and cleanup on the broker are in [06b](./06b-home-assistant). The unit is needed only
for the command items; everything else runs with the CAN bus disconnected.

Keep a second terminal running `mosquitto_sub -h <broker> -v -t '<prefix>/#' -t 'homeassistant/#'`
for the whole scenario: **there is no reply topic** — a refused command is visible only as
`mqtt: command refused: <reason>` in the device log (`GET /api/log`) and as `mqtt.rejected` in
`GET /api/status`. Discovery documents are retained: do the first run on a test broker, or be ready
to remove them with `mosquitto_pub -r -n -t <topic>`.

## Saving settings and the reconnect ladder

Failure classes and their waits: `dns`, `tcp`, `unavailable` → 2, 4, 8, 16, 32 s, then 60 s;
`dropped` → 1 s doubling to 60 s; `protocol` and `bad-credentials` → 300 s flat; every wait jittered
to 80–120 %. Socket timeout 2 s. As-built: [Reconnect and backoff](/interfaces/mqtt#reconnect-and-backoff).
